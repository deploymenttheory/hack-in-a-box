# Outcome follow-through (#117): implementation boundary

This deliverable includes native persistence, APIs and usable authenticated UI.
It does not depend on results/awards, create external tickets, reopen competition
records or turn an estimate/self-report into demonstrated adoption.

## Resources and authority

A top-level own/general pitch can be created by any current active application
member, without event membership or an event-workspace guard. It initially has
no event/team provenance. Only its current author sees its private draft; a
reasoned submission for organisation review makes the proposed fields available
to current event organisers, without granting them unrelated private evidence.
An organiser deliberately adopts it into their authorised event. Existing team
ideas validate current native team membership and the live-output gate.

Outcome history is immutable, separately versioned and reasoned. Current author,
explicit current owner, current source-team members and the applicable current
organisers have precisely scoped capabilities; departed/inactive grants are
rechecked. Adoption never discloses a draft event's name/configuration to an
ordinary author. Owner selection is limited to the current author, eligible
source-team members and current event organisers, not a generic person directory.

Organisers attach exact objective/measure versions through #156's native
organiser-authorised resolver. Ordinary authors cannot enumerate planning or
read private objective definitions through a reference. Restricted evidence is
always a distinct type from published fields. Demonstrated adoption requires a
source and observation date; estimates/self-reports remain labelled, and unknown
numeric values remain distinct from zero.

## Reviewed project publication

Publication has its own immutable draft/reviewed version and explicit reasoned
organiser action. It positively projects problem, solution, reviewed HTTPS links
and media references, intentionally shared event/team context and published
follow-up status. It never serialises a private outcome, evidence record or
assessment. Changing private progress does not silently publish that change.
Submission, awards, archive and a status change do not publish a project.

The searchable keyset-paginated catalog applies the reviewed organisation/event/
team audience and current reader/consent policy before returning cards/cursors.
Own-resource access does not grant a wider publication audience. Media references
are links only, never fetched/embedded automatically; identifiable subjects need
current native consent and organiser review. Revocation removes future reference
access, without claiming previously copied media can be recalled.

## Optional approved review schedules

30/60/90-day review plans are optional and use explicit event-timezone wall dates
with native ambiguity resolution. An outcome owner may record progress; only a
current organiser can approve exact plan/source/owner/template/audience/channel/
timing/provider revisions. Approval and progress are separate. Completion,
reassignment, event schedule or privacy-policy changes invalidate the old pending
plan. Rescheduling requires a new explicit exact approval, never consent transfer.
Lost responses reconcile the exact command/version before any retry; occurrence
and recipient identities are durable and deduplicated.

Current #78/#82 generic writes correctly freeze after archive. This domain adds
an audited outcome-specific update/plan path while keeping those generic guards
and competition records unchanged. A registered native outcome review source,
current owner/read authority, retained approval, event pause, privacy deadline and
provider unknown-attempt barriers remain authoritative on enqueue and send.
There is no second delivery engine. The in-app destination is the real top-level
outcome reader, backed by the current native owner policy on list/open/read.

#115 supplies the additive typed native ResourceReference retained in campaign
inbox provenance. #117 extends it with a narrowly registered outcome-owner path
for a current owner who has no event role. Generic EventRead, audience selection,
self-tests and CommunicationPeople membership rules remain unchanged. Historical
notification reads use immutable provenance plus current resource read authority,
not current due/open/approval eligibility.

## Verification to complete

Real PostgreSQL concurrency, exact command/revision replay, immutable history,
team/event isolation, independent published/private DTOs, current owner/person/
team/role revocation, actual provider/inbox delivery and archive retention.
Populated ordered migration follows the concrete merged #115 predecessor; the
current planned numbers40/41 are provisional until actual readiness ordering.

Actual ordinary no-event-role creator/owner HTTP and browser flows must cover
submission, own history, deliberate adoption, reviewed projects and approved
reminders. Desktop/mobile keyboard, current active-page revocation, stale edits,
validation, unknown writes and zero automatic replay need actual UI evidence.
No acceptance claim is made by this design document alone.

## Current implementation checkpoint

The native resource, private paged evidence, separately reviewed project projection,
exact command receipts and the existing durable automation/jobs/in-app path are
implemented. An actual archived organiser approval delivers to an active native
owner without event membership, without granting EventRead or disclosing a draft
event name. Historical inbox reads remain independent of later completion or
approval cancellation, while current resource ownership/retention still applies.
Owner-facing review projections contain schedule/status metadata, not organiser
message drafts or review reasons. Generic campaign approval remains separate.

The usable participant entry and owner forms have 18 desktop/mobile interaction
checks, including no-event-role submission, private storage exclusion, exact
response-lost receipts, explicit same-command retry, native rejection, active
revocation, transient read preservation and in-flight departure. Both app bundles
build. These checks are partial evidence, not completion of issue 117.

Remaining before readiness: actual current media-owner composition and ordered
predecessor migration preservation; organiser publication/reminder browser paths;
production-factory and SMTP ambiguous/fault proofs; final affected checks and
independent acceptance review. Media takes schema 41 first; outcomes will be
renumbered to 42 on the concrete media base. No results/awards capability is
claimed and no real external messages have been sent.
