## Quieter contributors and multiple teams

The multi-team scenario explicitly records a quieter competitor's demonstrated design explanation/error recovery under their person reference in a real mentor observation. An independent assessor attaches that exact authorised native observation version to a card. The input is factual demonstrated evidence, not commit counts or guessed contribution metrics. A separate team's unobserved categories remain pending; no team is ranked against another. Dashboard metadata excludes the private evidence and any score/rank/activity/comparison payload.

The fixture bootstraps synthetic people, teams and published mentor coverage. Its disbanded team represents an already-applied state from the separate team owner; this verification does not claim to retest team formation/rebalancing. It does use actual native draft saving, formal submission, common cutoff settlement, card writes, observation edits, feedback review/publication, mentor replacement, huddle configuration and decision commands. No frozen output, canonical proof or judge grant is fabricated for a passing assessment.

## Browser composition

`mentor-support-journey.spec.ts` uses a normal non-platform-admin session on the actual #105 review routes. It follows a permitted dashboard summary into the owning help detail, claims/transfers/resolves/reopens with native UI history, then returns to independent review and the intended panel. Support actions issue no moderation writes; private assessment never appears in help, and private help context never appears in the review projection. Leaving the panel clears unsent private decision input from the DOM without putting it in browser storage. Definite resource denial hides both owners' retained private payloads.

These deterministic browser API fixtures prove rendered UI navigation/privacy/request behavior, not PostgreSQL policy. The real PostgreSQL/HTTP tests above provide the domain/current-authority/transaction evidence. Existing #105 desktop/mobile cases are retained through a reusable fixture extraction, including organiser/primary/second permissions, factual judge preview, print exclusion, uncertain exact-history reconciliation and stale/deferred write guards. Native help browser coverage separately retains member creation, transfer targets, concurrent contexts, current access loss and event/account/session navigation.
