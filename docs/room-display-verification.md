# Room display verification

Issue #87 adds `/display/<event-id>` to the ordinary public build as a separate entry outside the account shell. A display accepts its event's temporary pairing key into component state only. It never loads a person session, participant resource, credential or organiser API. The key is sent only in the Authorization header; fetch omits cookies, URL credentials and caches. Disconnect, revocation and unmount discard the display session and revoke temporary image URLs.

The screen renders the server's complete approved current/next projection, including urgent cues. The feed additionally carries the latest explicitly published finalist and award snapshots; typed protocol parsing retains them, while visible result presentation is tracked in #113. It performs no result or private assessment lookup. Every complete snapshot replaces the previous one even if its cue sequence repeats: common content withdrawal and branding changes need not increment that sequence. Runtime parsing projects only the display fields, and bounded SSE framing (512 KiB per complete frame) handles split UTF-8/CRLF and coalesced frames.

Connection loss retains the last validated cue, labels the loss and last server update time, and reconnects with bounded backoff. An eight-second heartbeat deadline detects a stalled stream. Countdown ticks use the last server clock offset, remain fixed when held, and stop at zero. Reconnection takes the latest complete snapshot. Revoked/unauthorized capability responses clear the cue rather than retaining it as a disconnected screen.

## Branding and link boundaries

The existing #44 branding contract requires logos/icons as well as palette and missing-image defaults. Display snapshots therefore carry bounded approved asset metadata and SHA-256 digests, without image bytes or event definitions. `/api/v1/events/<event-id>/display/assets/<asset-id>` rechecks pairing and issuer authority and reads only a **current branding asset in that event**. It cannot interpret an ID as an event upload, attachment or foreign event file. PNG/JPEG assets were fully decoded on authoring writes; frequent projections recheck bounded image headers/types without allocating full raster pixels every second. Invalid legacy branding falls back to readable defaults. Browser image loading checks MIME, size and digest and uses temporary object URLs; missing/broken assets retain event text and a readable layout.

The visible destination and QR share one canonical approved HTTPS URL; embedded credentials and executable/relative URLs are withheld. QR codes use the real SVG encoder with a four-module quiet margin and explicit black/white contrast. Official contracts checked during implementation: [qrcode.react](https://github.com/zpao/qrcode.react) and the independent test decoder [jsQR](https://github.com/cozmo/jsQR). There is no URL shortening service or fabricated short alias: the MC's approved supplied URL is displayed verbatim after canonicalization.

Current live snapshots contain only the latest publication of each kind; the separately authorised results API retains historical releases.
