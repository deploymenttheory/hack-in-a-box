## Invitation scope and provider limits

Issue #59 explicitly permits opaque invitation codes **or** verified captain identity. The implemented path uses an opaque UUID scoped to its event. Display names are not join keys and duplicate names remain valid. There is no email-matching input or user-directory lookup; this audit does not claim email normalization is implemented.

The current boundary records one durable publication intent for future communications/repository consumers. Unpublished suggestions emit none. Repository provisioning, remote provider permission reconciliation and judging remain their separate backlog deliverables. Current retirement evidence proves an inactive entry, withdrawn outcome, no scored revision and an unused retained repository reference; it does not claim a live GitHub repository or judging provider was exercised.
