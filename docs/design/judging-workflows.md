# Independent judge desk

Both portals expose `/events/{event}/judging` and the separately labelled
`/events/{event}/judging/practice`. They consume the real #108 versioned contracts;
visiting either portal grants no authority. The desk reads current native event,
role context, published current/next room programme and exact own assignments.
Assignment order is not represented as a presentation schedule. Every selected
build mounts its own current authorised brief; grants are never inferred from an
admin team/repository directory. Native conflict, cutoff, finalist, frozen final
and exact code-receipt gates remain decisive.

The flat Fleet collection leads to a focused review desk: frozen artifacts and
code evidence, reviewed factual mentor summary, published rubric/version and
anchors, independent draft, captured review, exact acknowledged save or locked
submission, then next assigned build. `JudgeBriefing`, `JudgeRubric`,
`JudgeScoreFields`, `JudgeScoreSummary` and `JudgeReview` are actual production
exports. The separately hosted guide imports them with synthetic local callbacks;
its copyable snippet and accessibility/anti-pattern guidance define ownership.
The native owner supplies protected frozen artifact links. Pure guide presentation
never requests a file, account, API or provider.

Private score/evidence drafts and captured bodies live only in mounted owners.
Native field validation retains input and focuses the invalid control. Current
source/card drift pauses commands for explicit review of a fresh saved starting
point; it does not silently retarget a draft. Current permission/assignment/source
loss disposes private descendants and fences late reads/continuations. Temporary
outages retain unsent work while pausing writes. All private views and review
portals are excluded from print. Saved draft, submitted lock, synthetic practice
and unknown original outcome have distinct labels.

The actor/event/session command namespace retains only fixed-label original UUID,
version, run/team identity and request fingerprint above private task lifetimes.
Matching native original acknowledgements can settle that metadata even when the
private task ended. Current reads and new actions never settle an older unknown.
A deliberate retry can repeat the exact captured body/key/version only while it
still exists in the original mounted task. No full offline judging or automatic
replay is provided. An explicitly reviewed new starting point permits a different
command while preserving the older original unknown metadata.

Organiser reopening uses the separate current metadata-only card-state API.
An organiser captures author/version/final/opaque decision and recorded reason;
private scores/notes/code never enter that coordination owner. Reopen is not a
resubmission and invalidates affected unannounced result approvals natively.
Qualification finalists remain the real #110 policy; there is no UI permission or
qualification scoring shortcut. Award tally/ties/publication belong to #112.

The presentation owner supplies the separate generated
`GET /events/{event}/judging/presentation-order` read projection. It returns only
published, currently public-to-room cue titles, compact visible ordinals and a
current marker. It reuses the native display release filter; embargoed content,
draft programmes, content bodies/URLs, pairing/control secrets and team-to-cue
associations never enter this projection. Current native judge assignment/conflict
or organiser authority is required on every read. An active MC override is
labelled without projecting its private payload or marking a programme cue as
current. This read seam supplies no scoring or MC mutation permission.

The desk uses actual event branding and event-local cutoff context. Its frozen
build destination is the independently authorised submitted-build reader with
`judge_run` context. The reader performs its own exact-team and native artifact
reads; a desk link does not transfer authority or score data.
